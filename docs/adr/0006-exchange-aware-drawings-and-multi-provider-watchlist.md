# 0006. Exchange-Aware Drawing Isolation and Multi-Provider Watchlist Architecture

Untuk mencegah kebocoran coretan gambar analisis lintas bursa, hilangnya identitas bursa pada daftar pantau (*watchlist*), serta pemicu palsu kegagalan koneksi (*Network Error*) saat beralih koin antar bursa, `trawangan` menetapkan keputusan arsitektur berikut:

1. **Exchange-Aware Drawing Isolation**: Mengikat persistensi gambar teknikal secara mutlak pada pasangan `(providerId, symbol)` (misal `binance:BTCUSDT`, `bitunix:BTCUSDT`, `indodax:BTCIDR`). Kanvas WebGL2 Vela wajib mengosongkan layer gambar aktif saat simbol atau bursa berganti, lalu memulihkan (*restore*) gambar spesifik milik instrumen target dari SQLite lokal. Data gambar lawas tanpa prefix bursa dipetakan ke `binance` sebagai warisan (*legacy fallback*).
2. **Exchange-Aware Watchlist Data Model**: Menyimpan item pada daftar pantau dengan identitas bursa eksplisit (`${providerId}:${symbol}`) dengan dukungan migrasi transparan untuk data lama. Menampilkan chip badge visual bursa (`BINANCE`, `BITUNIX`, `INDODAX`) pada bilah sisi antarmuka, di mana klik pada item langsung mengarahkan kanvas ke bursa dan simbol asalnya secara deterministik.
3. **Multi-Provider Watchlist Polling Multiplexer**: Mengelompokkan instrumen daftar pantau berdasarkan bursanya saat siklus polling latar belakang berjalan, sehingga permintaan ticker hanya dialirkan ke adapter pasar yang relevan. Hal ini mengeliminasi kesalahan permintaan koin USDT ke Indodax atau koin IDR ke Bitunix yang sebelumnya memicu peringatan *Stalled/Blocked Feed* palsu.
4. **Multi-Chart Sync Boundary**: Membatasi sinkronisasi gambar antar sel grafik pada tata letak multi-chart hanya jika kedua sel grafik membuka bursa dan instrumen yang identik, guna menghindari distorsi koordinat harga akibat disparitas pasar.
